# 03 — วิเคราะห์ความน่าจะเป็นที่จะทำกำไรได้อย่างต่อเนื่อง

> ตัวเลขทุกตัวคำนวณจากสูตรใน [02_math_framework.md](02_math_framework.md) และเก็บไว้เป็นตารางใน [`data/scenarios.yaml`](../data/scenarios.yaml)
> **สมมติฐานร่วม:** ผลตอบแทนรายวัน i.i.d. ใกล้ normal, vol 10%/ปี (ยกเว้นระบุ), ระยะ 3 ปี
> ในโลกจริงมี fat tail และระบอบตลาดเปลี่ยน ตัวเลขจริงจึง**แย่กว่านี้** โดยเฉพาะกลยุทธ์ที่ skew ติดลบ

## 2. คำตอบหลัก: ความน่าจะเป็นตามแนวทาง (Scenario, F29)

| Scenario | P(edge จริง) | SR live ถ้าจริง / ถ้าไม่จริง | บวกรวม 3 ปี | ผ่อนปรน | **เข้มงวด** |
|---|---|---|---|---|---|
| **A** ซื้อ EA/signal ทั่วไป | 3% | 0.5 / −0.5 | 18.8% | 18.6% | **0.4%** |
| **B** สร้าง EA เอง optimize ใน MT5 แต่ไม่มี validation เชิงสถิติ | 10% | 0.5 / −0.3 | 32.9% | 32.5% | **1.3%** |
| **D** LLM agent ตัดสินใจเทรดเอง | 10% | 0.5 / −0.5 | 23.1% | 22.9% | **1.0%** |
| **C** Pipeline เข้มงวด + กระจาย trend/carry/MR + ¼–½ Kelly | 60% | 0.8 / −0.3 | 65.3% | 64.9% | **10.4%** |
| **C+** C ที่ผ่าน live incubation แล้ว | 70% | 1.0 / −0.3 | 75.1% | 74.8% | **17.8%** |

**อ่านตารางนี้อย่างไร**
1. แม้**ไม่มี edge เลย** ก็ยังมีโอกาส ~17–28% ที่ 3 ปีจะออกมาเป็นบวกเพราะโชค ผลบวกช่วงสั้นจึง**ไม่ใช่หลักฐาน**ว่ามี edge
2. ตัวแปรที่ทำให้ B ต่างจาก C คือ **P(edge จริง)** (มาจาก validation) และ **SR live** (มาจากการกระจายความเสี่ยงและต้นทุนต่ำ) ไม่ใช่ความฉลาดของสัญญาณ
3. ถ้าเป้าหมายคือ "กำไรทุกปี DD ต่ำ" แม้ระบบที่ดีที่สุดใน scenario นี้ก็ทำได้แค่ ~10–18% เท่านั้น

## 3. ข้อค้นพบเชิงคณิตศาสตร์ 7 ข้อ

### 3.1 "กำไรทุกเดือน" ไม่สอดคล้องกับระบบที่ซื่อตรง (ตาราง T2)
| SR ต่อปี | P(เดือนใดเดือนหนึ่งกำไร) | P(≥10/12 เดือน) | P(12/12 เดือน) |
|---|---|---|---|
| 0.5 | 55.7% | 4.7% | 0.1% |
| 1.0 | 61.4% | 9.9% | 0.3% |
| 2.0 | 71.8% | 29.9% | 1.9% |
| 3.0 | 80.7% | 58.2% | 7.6% |

→ EA ที่ "กำไรทุกเดือนติดกันหลายปี" น่าจะเป็น **grid/martingale ที่ tail risk ยังไม่เกิด** หรือเป็นข้อมูลที่ถูกคัดมา

### 3.2 การ optimize คือตัวสร้าง Sharpe ปลอม (ตาราง T3, T5)
- ลอง **45 แบบบน 5 ปี** → เจอ SR ≈ 1.0 จากโชคล้วน
- MT5 genetic optimizer ที่ลอง **10,000 แบบบน 3 ปี** → เจอ SR ≈ 2.2 จาก noise
- เห็น SR 1.5 บน backtest 3 ปี: ถ้าลองแบบเดียว DSR = 0.995 (เชื่อได้) แต่ถ้าลอง 100 แบบ DSR = 0.53 (**ไม่ต่างจากโยนเหรียญ**)
- เกณฑ์ t > 3 แปลว่า SR 1.0 ต้องใช้ข้อมูล ≥ 9 ปี และ SR 2.0 ต้องใช้ ≥ 2.25 ปี

### 3.3 ต้องรอผล live นานแค่ไหนถึงเชื่อได้ (ตาราง T4)
| SR | MinTRL (ปี, 95%) normal | skew −3 / kurt 30 |
|---|---|---|
| 0.5 | 10.8 | 11.9 |
| 1.0 | 2.7 | 3.3 |
| 2.0 | 0.7 | 1.0 |

→ ระบบที่ SR จริงประมาณ 1 ต้องเห็น live ราว 3 ปีจึงจะพิสูจน์ได้ทางสถิติ ช่วง incubation 6–12 เดือนจึงใช้**คัดตัวที่พังออก**ได้ แต่ยังพิสูจน์ไม่ได้ว่าตัวที่เหลือมี edge

### 3.4 ต้นทุนและขนาดไม้ชี้ขาดการอยู่รอด (ตาราง T7)
ระบบ win 50%, +1.5R / −1R:
| ต้นทุน/ไม้ | E สุทธิ | RoR @ risk 3%/ไม้ (D=10) | RoR @ risk 1%/ไม้ (D=30) |
|---|---|---|---|
| 0.0R | 0.25R | 4.1% | 0.007% |
| 0.1R | 0.15R | 14.7% | 0.32% |
| 0.2R | 0.05R | 52.7% | 14.7% |

→ ระบบเดิมแต่ **stop แคบลง** (ต้นทุนเป็น R จึงสูงขึ้น) และ **risk ต่อไม้สูงขึ้น** ทำให้ RoR เพิ่มขึ้นได้กว่า 7,000 เท่า

### 3.5 Kelly: ความผันผวนที่ full Kelly เท่ากับ SR
- ที่ full Kelly พอร์ตมี vol ต่อปี ≈ SR (เช่น SR 0.8 → vol 80%)
- โอกาสที่พอร์ตจะ**ลดลงครึ่งหนึ่ง** ณ จุดใดในอนาคต: full Kelly 50%, ½ Kelly 12.5%, ¼ Kelly 0.8% (ตาราง T6)
- **กับดัก:** ถ้าประเมิน SR สูงเกินจริง 2 เท่า (ซึ่งเกิดบ่อยจากข้อ 3.2) half-Kelly จะกลายเป็น full Kelly ทันที → ควรใช้ **¼ Kelly ของ SR หลัง shrinkage/haircut**
- ตัวอย่างที่สมเหตุสมผล: SR 0.8, vol 10–20% → ผลตอบแทนคาดหวังราว **7–14%/ปี** ส่วน "20%/เดือน" ต้องใช้ leverage เกิน Kelly หลายเท่า ซึ่งในระยะยาวคือการเดินไปสู่ ruin

### 3.6 Martingale/Grid: ruin เป็นเรื่องของ "เมื่อไร" (ตาราง T8)
- เพิ่มไม้ 2 เท่าได้สูงสุด 8 ครั้ง ที่ q = 0.5: ล้มเหลว 0.39% ต่อรอบ → คาดว่าจะ ruin ภายใน **~256 รอบ** และ EV ต่อรอบ = **0**
- ถ้ามี spread (q = 0.52): ภายใน 1,000 ไม้มีโอกาส **92.6%** ที่จะเจอแพ้ติดกัน 8 ไม้ และ EV ติดลบ
- Win rate 99% ที่เห็นจึงเป็นภาพลวงจากหางของการแจกแจงที่ยังไม่เกิด

### 3.7 การกระจายช่วยได้จริง แต่ต้องเป็นของที่ไม่ correlate กัน (ตาราง T11)
- 10 กลยุทธ์ SR 0.5, ρ = 0.2 → SR พอร์ต **0.94**
- ถ้า ρ = 0.8 (เช่น EA หลายตัวบน XAUUSD ตัวเดียว) → **0.55** แทบไม่ดีขึ้น

### 3.8 (โบนัส) Prop firm (ตาราง T9)
- ถ้า edge = 0 จะผ่าน 2 phase ได้ 33% แต่อัตราผ่านจริงอยู่ที่ 5–14% → ผู้เข้าแข่งขันโดยเฉลี่ยมี **edge ติดลบหลังต้นทุน** และ/หรือเสี่ยงเกินจนชน daily limit
- ถ้ามี edge จริง (SR 1) การ**ลด vol** จาก 40% เหลือ 10% เพิ่มโอกาสผ่านจาก 46% เป็น 80%

## 4. Sensitivity — คันโยกไหนเปลี่ยนความน่าจะเป็นมากที่สุด

| คันโยก | ตัวแปรที่เปลี่ยน | ผลต่อ P(บวก 3 ปี) โดยประมาณ |
|---|---|---|
| Validation เข้มงวด (DSR/PBO/SPA + incubation) | P(edge จริง) 10% → 60% (SR live คงที่ 0.5) | **+26 จุด** (32.9% → 58.6%) |
| กระจายความเสี่ยงไปยัง edge ที่ correlation ต่ำ | SR live 0.5 → 0.8 | +11 จุดเมื่อ edge จริง (+7 จุดโดยรวม → 65.3%) |
| ลดต้นทุน/ขยาย stop | E สุทธิ, SR | ตัดสินว่า edge อยู่หรือหาย |
| ลด risk ต่อไม้ / ใช้ ¼ Kelly | RoR, P(DD) | RoR ลดจาก % เป็น ‰ |
| เลี่ยง martingale/grid | ruin | จาก "แน่นอนในระยะยาว" → ควบคุมได้ |
| ใช้ LLM เป็นผู้ตัดสินใจหลัก | P(edge), variance | **ลดลง** ตามหลักฐานปัจจุบัน |

## 5. Decision gates (ใช้เป็นเกณฑ์ go/no-go ก่อนเขียนโค้ดจริง)

| Gate | เกณฑ์ผ่าน | Entity ที่เก็บผล |
|---|---|---|
| G0 Hypothesis | มี `edge_source` ที่ไม่ใช่ `none_identified` และไม่อยู่ในกลุ่ม `avoid` | `StrategySpec` |
| G1 Backtest | สุทธิหลังต้นทุน ×1.5 ยังมี SR > 0, ความยาวข้อมูล ≥ MinBTL(N), t > 3 **หรือ** DSR ≥ 0.95 | `ValidationReport` |
| G2 Robustness | PBO ≤ 0.2, WFE ≥ 0.5, ≥ 70% ของ parameter ข้างเคียงยังมี SR > 0, SPA p < 0.05 | `ValidationReport` |
| G3 Incubation | paper/live ขนาดเล็ก 6–12 เดือน, SR live ≥ 50% ของ backtest, slippage อยู่ในกรอบที่ model ไว้ | `LiveMonitor` |
| G4 Deploy | ¼ Kelly ของ SR_post, RoR(DD 20%) < 1%, daily loss limit, kill switch ที่ MC DD p99 หรือ CUSUM | `RiskPlan` |
| G5 Monitor | อัปเดต Bayes ทุกเดือน (F21) และลดขนาดเมื่อ posterior SR ลดลง | `LiveMonitor` → `EdgePosterior` |

## 6. ข้อสรุป

1. **"กำไรทุกเดือน"** เกือบเป็นไปไม่ได้ทางคณิตศาสตร์สำหรับระบบที่ไม่ซ่อน tail risk (< 2% ต่อปีแม้ SR 2)
2. **"กำไรสะสมในระยะ 3 ปีแบบ DD คุมได้"** เป็นไปได้จริง แต่โอกาสแตกต่างกันมากตามกระบวนการ คือราว 19% (ซื้อ EA), 23% (LLM ตัดสินใจเอง), 33% (สร้างเองโดยไม่ validate) และ **65–75%** (pipeline เข้มงวดที่กระจาย edge)
3. ปัจจัยที่สำคัญที่สุดเรียงตามลำดับคือ **(1) ไม่ใช้ martingale/grid (2) ต้นทุนต่ำเมื่อเทียบกับ R (3) นับ N trials แล้วใช้ DSR/PBO (4) ¼ Kelly (5) กระจาย edge ที่ไม่ correlate กัน** ส่วนการเลือกโมเดล AI ที่ฉลาดที่สุดสำคัญน้อยกว่าทั้งหมดนี้
4. บทบาทที่เหมาะกับ **AI Agent** คือผู้ช่วยวิจัย (ทุก idea ต้องลง TrialRegistry) ตัวกรองข่าว/ระบอบ และผู้สรุปรายงาน ส่วน signal, sizing และ execution ควรเป็นแบบ deterministic
5. ผลตอบแทนที่สมเหตุสมผลของระบบที่ดีอยู่ในระดับ **หลักหน่วยถึงสิบกว่า %/ปี** ไม่ใช่ %/เดือน

## 7. ข้อจำกัดของการวิเคราะห์นี้
- สมมติ normal/i.i.d. ทำให้ความเสี่ยงของกลยุทธ์ที่ skew ติดลบ (carry, MR, grid) **ต่ำกว่าความจริง**
- Prior (π) และ SR live เป็นค่าประมาณจากหลักฐานรวม จึงต้องแทนด้วยค่าที่วัดจากระบบจริงตาม pipeline
- ตัวเลข Monte Carlo มีความคลาดเคลื่อน ~±1–2 จุดเปอร์เซ็นต์
- ข้อมูล prop firm และ Alpha Arena บางส่วนมาจากแหล่งระดับ C/B ซึ่งเป็นการแข่งขันช่วงสั้น
